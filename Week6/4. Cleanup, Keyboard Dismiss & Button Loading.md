# Cleanup, Keyboard Dismiss \& Button Loading State


***

## 🗺️ What This Stage Covers

These improvements the production-quality

- 🧹 `dispose()` — properly clean up memory when the screen closes
- ⌨️ Keyboard dismiss — hide the keyboard automatically when Search is tapped
- 🔒 Button loading state — disable the button while a request is in progress so it can't be tapped twice

## Part 1 — `dispose()`


***

### Why `dispose()` Exists

Every `TextEditingController` you create **occupies memory**. When the user navigates away from the screen, the `State` object is destroyed — but the controller keeps living in memory unless you explicitly clean it up. This is called a **memory leak**.[^1]

***

### Where to Add It

Add this method inside `_HomeScreenState`, directly **below your state variables** and **above** `_fetchWeather()`:

```dart
  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }
```
|  |  |
| :-- | :-- |
| `@override` | You're replacing the default `dispose()` from the parent `State` class |
| `void dispose()` | Called automatically by Flutter when this screen is removed from the widget tree |
| `_controller.dispose()` | Frees the memory held by your `TextEditingController` |
| `super.dispose()` | **Always call this last** — it lets the parent class finish its own cleanup |

> ⚠️ `super.dispose()` must be the **last line** inside `dispose()`. Calling it before `_controller.dispose()` can cause errors because the parent tears down resources your controller still needs.

> 🧪 **Test:** This has no visible effect — it's invisible cleanup. To confirm it works, add `print('disposed')` before `super.dispose()`, navigate away from the screen, and check the console. You'll see `disposed` printed. Remove the print after testing.

## Part 2 — Keyboard Dismiss


***

### The Problem

When the user taps **Search**, the keyboard stays open and covers the weather card. The user has to manually tap elsewhere to close it — this is poor UX.

***

### Where to Add It

Inside your `_fetchWeather()` method, add **one line** at the very top — before `setState()`:

```dart
  Future<void> _fetchWeather() async {
    FocusScope.of(context).unfocus();   // ← ADD THIS LINE

    setState(() {
      _isLoading = true;
      _errorMessage = null;
    });
    // ... rest of the method stays the same
  }
```

|  |  |
| :-- | :-- |
| `FocusScope` | Flutter's system that tracks which widget currently has keyboard focus |
| `.of(context)` | Finds the `FocusScope` for the current screen using the widget tree |
| `.unfocus()` | Removes focus from the `TextField` — this automatically closes the keyboard |

> 🧪 **Test:** Tap the `TextField`, type a city, then tap Search. The keyboard should **immediately disappear** before the spinner appears. If the keyboard stays open — make sure `FocusScope.of(context).unfocus()` is the very first line inside `_fetchWeather()`.

## Part 3 — Button Loading State


***

### The Problem

Right now, if the user taps **Search** while a request is already running, it fires **a second API call** on top of the first one. This can cause the screen to flicker or display outdated data.

***

### Change 1 — Disable the Button While Loading

Find your `ElevatedButton` in the `build()` method:

```dart
ElevatedButton(
  onPressed: _fetchWeather,
  child: const Text('Search'),
),
```

Replace it with:

```dart
ElevatedButton(
  onPressed: _isLoading ? null : _fetchWeather,
  child: const Text('Search'),
),
```

**What changed**

|  |  |
| :-- | :-- |
| `_isLoading ? null : _fetchWeather` | A **ternary expression** — if loading, pass `null`; otherwise pass the method |
| `onPressed: null` | In Flutter, setting `onPressed` to `null` **automatically disables** the button and greys it out |
| `onPressed: _fetchWeather` | When not loading, the button works normally |

> ⚠️ This is the Flutter-idiomatic way to disable a button — you do **not** need an `isEnabled` property. `null` is the switch.

***

### Change 2 — Show a Spinner Inside the Button

Replace the same `ElevatedButton` again with this final version:

```dart
ElevatedButton(
  onPressed: _isLoading ? null : _fetchWeather,
  child: _isLoading
      ? const SizedBox(
          width: 20,
          height: 20,
          child: CircularProgressIndicator(
            strokeWidth: 2,
            color: Colors.white,
          ),
        )
      : const Text('Search'),
),
```

|  |  |
| :-- | :-- |
| `_isLoading ? ... : ...` | Another ternary — swaps the button's label for a spinner while loading |
| `SizedBox(width: 20, height: 20)` | **Required** — `CircularProgressIndicator` expands infinitely without a size constraint |
| `strokeWidth: 2` | Makes the spinner ring thin — a thick ring looks oversized inside a small button |
| `color: Colors.white` | White spinner on the button's default blue — stays visible |
| `: const Text('Search')` | When not loading, show the normal label |

> 🧪 **Test:** Tap Search on a slow connection (or add `await Future.delayed(const Duration(seconds: 3))` at the top of `_fetchWeather()` temporarily). You should see:
> - The button text replaced by a small white spinner
> - The button greyed out — tapping it again does nothing
> - After 3 seconds, the weather card appears and the button returns to normal
> Remove the `Future.delayed` line after testing.
