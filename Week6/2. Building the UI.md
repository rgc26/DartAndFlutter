## `lib/screens/home_screen.dart`

Create a new folder `screens/` inside `lib/`, then create the file:

```
lib/screens/home_screen.dart
```

> This file's **only job** is to display weather data and handle user input. It does not know how the API works — it just asks the service and shows what comes back.

***

### Line 1: Import Flutter's Material Library

```dart
import 'package:flutter/material.dart';
```

**Why?**

- `material.dart` gives you every Flutter UI widget — `Scaffold`, `Text`, `TextField`, `ElevatedButton`, `Column`, etc.
- Without this, you cannot build any visual screen in Flutter
- It is always the **first import** in any screen file

### Line 4: Declare the Class as a `StatefulWidget`

**What this means**


| Word | Meaning |
| :-- | :-- |
| `StatefulWidget` | A widget that can **change** — your screen updates when weather data loads |
| `const HomeScreen({super.key})` | The constructor — `const` means it can be cached for performance |
| `super.key` | Passes an identity key to Flutter's widget system — always include this |
| `createState()` | Tells Flutter which State class manages this widget's data |
| `_HomeScreenState` | The `_` prefix makes it **private** — only this file uses it |

> ⚠️ Use `StatefulWidget` (not `StatelessWidget`) whenever your screen needs to **update** after it first loads — like showing data after an API call.

### Lines 9–22: Write the Fetch Method

```dart
  Future<void> _fetchWeather() async {
    setState(() {
      _isLoading = true;
      _errorMessage = null;
    });

    try {
      final weather = await _service.fetchWeather(_controller.text);
      setState(() {
        _weather = weather;
        _isLoading = false;
      });
    } catch (e) {
      setState(() {
        _errorMessage = e.toString();
        _isLoading = false;
      });
    }
  }
```

Let's break this down **line by line:**

#### The Method Signature

```dart
Future<void> _fetchWeather() async {
```

| Part | Meaning |
| :-- | :-- |
| `Future<void>` | This method is async but returns **nothing** — it just updates the screen's state |
| `_fetchWeather` | Private method name — `_` means only this class uses it |
| `async` | Required because we use `await` inside |

#### Trigger the Loading State

```dart
    setState(() {
      _isLoading = true;
      _errorMessage = null;
    });
```

- `setState()` = tells Flutter **"data changed — redraw the screen"**
- `_isLoading = true` = the spinner will appear
- `_errorMessage = null` = clears any old error before a new search


#### Call the Service

```dart
    final weather = await _service.fetchWeather(_controller.text);
```

- `_controller.text` = reads exactly what the user typed in the `TextField`
- `await` = pauses until the API responds
- `weather` = holds the returned `WeatherModel` object


#### Update the Screen with Results

```dart
      setState(() {
        _weather = weather;
        _isLoading = false;
      });
```

- `_weather = weather` = saves the result so the `build()` method can display it
- `_isLoading = false` = hides the spinner
- Wrapping in `setState()` triggers a **screen redraw** immediately


#### Handle Errors

```dart
    } catch (e) {
      setState(() {
        _errorMessage = e.toString();
        _isLoading = false;
      });
    }
```

- `catch (e)` = catches anything thrown by `fetchWeather()` — like a 404 or 401
- `e.toString()` = converts the error into readable text shown on screen
- `_isLoading = false` = always turn off the spinner, even on failure

## `lib/main.dart`

This is the **entry point** — the very first file Flutter runs. Open the existing `main.dart` and replace everything.

***

### Line 1: Import Material

```dart
import 'package:flutter/material.dart';
```

**Why?**

- `main.dart` needs `MaterialApp` — the root widget that sets up themes, navigation, and the app title
- Same rule as `home_screen.dart` — always import `material.dart` in any Flutter file that builds UI

***

### Line 2: Import Your Screen

```dart
import 'screens/home_screen.dart';
```

**Why?**

- `main.dart` is in `lib/` — so no `../` needed to reach `screens/`
- Without this, `MaterialApp` doesn't know what `HomeScreen` is

***

### Line 3: The `main()` Function

```dart
void main() {
  runApp(const MyApp());
}
```

**What this means:**


| Part | Meaning |
| :-- | :-- |
| `void main()` | The starting point of every Dart program — Flutter calls this first |
| `runApp(...)` | Hands control to Flutter — it takes your widget and draws it on screen |
| `const MyApp()` | Your root widget — `const` means Flutter builds it once and caches it |


***

### Lines 4–14: The Root App Widget

```dart
class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Weather App',
      debugShowCheckedModeBanner: false,
      home: const HomeScreen(),
    );
  }
}
```

**What this means:**


| Line | Why |
| :-- | :-- |
| `StatelessWidget` | `MyApp` never changes — it just points to `HomeScreen` |
| `MaterialApp` | The root wrapper — sets up Material Design for the whole app |
| `title: 'Weather App'` | The app name shown in the device task switcher |
| `debugShowCheckedModeBanner: false` | Hides the red "DEBUG" banner in the top-right corner |
| `home: const HomeScreen()` | Sets `HomeScreen` as the first screen that loads |
